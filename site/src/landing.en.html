writing as a resumable state machine

CanonLoom is not a black box that claims to generate an entire novel from one prompt. It breaks a chapter's production into seven strongly-constrained S0–S6 stages. The author makes choices and approvals at every step; Python does deterministic validation; the agent handles the creative work. The protocol lives in files, not in the model's memory.

Every chapter walks through S0–S6. No layer depends on a model's hidden memory, and failures can be traced to a specific stage.

  12. →

  14. →

Without an S6 approval file, a draft never promotes to manuscript/. Stages cannot be skipped; state promotion requires the author.

The problem it solves

Long fiction usually breaks between chapters: motivations drift, timelines contradict, unapproved assumptions quietly become "story facts".

🧭

State drift

Character goals, knowledge, and world rules shift silently between chapters. Made explicit as files, the drift can be detected.

📄

Unapproved promotion

A setting the model invents becomes a "fact" once it is written into prose. S0–S6 gates keep candidates from being decisions.

🔎

Untraceable review

"What is this paragraph based on? Was that review comment fixed?" — each context package records source SHA-256 fingerprints.

✋

Suggestions vs decisions

AI options, agent picks, and author approvals are stored separately. AI inference never auto-enters canon.

Author intent → chapter contract → draft → review

The creative loop grows possibility (diverge → compare → select → compose); the governance loop controls commitment (retrieve → verify → review → settle).

The author's daily routine is a short set of commands

~/my-novel
$ ./bin/canonloom init ~/my-novel --name "My Novel"
✓ project initialized (0.2.1)
$ ./bin/canonloom --root ~/my-novel setup --confirm
✓ AUTHOR_SETUP_CONFIRMED
$ ./bin/canonloom --root ~/my-novel idea
→ generated 3 candidate directions
   [1] a locked room and an unreliable witness
   [2] ...
$ ./bin/canonloom --root ~/my-novel status
STAGE: ideation · next_action: Start ideation
LANGUAGE: en · WORKFLOW: standard
$ ./bin/canonloom --root ~/my-novel continue
✓ current.md updated — agent reads tasks/current.md
$ ./bin/canonloom --root ~/my-novel diagnose
✓ structure OK

Commands only prepare readable task files. The agent reads tasks/current.md, does the work, and writes artifacts to the agreed directories.

  • status — which stage am I in?
  • continue — follow the next_action (most used)
  • diagnose — run this first when something breaks
  • repair — fix whitelisted structural issues
  • state report — summarize optional narrative state

Design "no"s

Not a GUI editor

It does not turn the author into an operator inside an interface.

No multi-model by default

A single primary model + Python deterministic tools avoids state divergence.

No graph database

The early problem is not query performance; it is state boundaries.

Numbers are not quality

"Fewer tokens" or "higher scores" are not literary quality.

Run the minimal pipeline in five minutes

No third-party packages — just Python 3.9+.
