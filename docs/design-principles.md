# Design principles

## Author sovereignty

The author owns intent, canon, interpretation, and final acceptance. Automation can reduce effort but cannot transfer authorship by default.

## Minimal necessary context

More context is not automatically better. The compiler should prefer the smallest versioned evidence package that can support the current task.

## Controlled divergence

Creative variety belongs before commitment. Agents may disagree and explore, but the project must have one selected execution path at drafting time.

## Evidence over confidence

Every important finding or state change should identify the text, decision, or source supporting it. Confidence without evidence is only a proposal.

## Separation of concerns

Planning, generation, review, and settlement have different failure modes and should remain independently inspectable.

## Reversible decisions

Candidate memory and draft changes should be easy to reject or supersede. Promotion to canon should be explicit and logged.

## Quality is multidimensional

Continuity, causality, style, pacing, reader promise, and author intent should not be collapsed into one score.

## Productive restraint

The system should prevent accidental resolution, unsupported invention, and context overload without dictating the prose.
